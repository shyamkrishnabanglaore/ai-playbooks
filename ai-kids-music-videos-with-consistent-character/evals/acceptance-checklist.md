# Acceptance checklist

Record each item as pass, fail, or not verified with brief evidence.

## Plan and approval

- [ ] Song theme, language, character source, and intended audience are clear.
- [ ] A production brief lists the song, fixed landscape 16:9 ratio, visual style, scene plan, generation counts, and private export plan.
- [ ] GO was received before generation or upload.
- [ ] No unapproved purchase, public sharing, destructive deletion, or unrelated account change occurred.

## Song and character

- [ ] Song is original, age-appropriate, and completed; its actual duration and asset ID are recorded.
- [ ] Character bible captures stable visual identity and is frozen.
- [ ] Canonical reference is selected and visually checked for clear identity and obvious defects.
- [ ] 16:9 is confirmed on the reference and storyboard assets.

## Storyboard and animation

- [ ] Scene order follows the song's story and maps to lyrics or musical beats.
- [ ] The full character bible appears in each final scene prompt.
- [ ] One clear action, readable framing, and compatible prop support are described per scene.
- [ ] Selected images preserve species/person type, face, colors, outfit, and signature accessory.
- [ ] Video prompts use pose-compatible movement and retain 16:9 framing.
- [ ] Clip generation count matches selected storyboard scene count, with each completed job mapped to its scene.
- [ ] Any retries followed the two-retry-per-failed-scene bound and preserved successful assets.

## Timeline, export, and delivery

- [ ] One clip per selected scene appears in the intended order; no duplicate or missing timeline clips.
- [ ] The exact generated song appears once on the audio track at the beginning.
- [ ] Timeline ending is checked against song duration; any sync mismatch is measured and reported.
- [ ] Complete timeline was reviewed for pacing, song/story alignment, and obvious visual/audio issues.
- [ ] Editable project save status and name are verified.
- [ ] Export is confirmed as queued or completed; the report distinguishes those states.
- [ ] Export ratio is 16:9; MP4 file is opened if download and inspection are supported.
- [ ] Final report includes actual duration, scene count, export location/status, checks, and unverified limitations.

## Recovery

- [ ] Existing jobs were checked before retries or resubmission.
- [ ] Work resumed from verified state without duplicating completed actions.
- [ ] Any blocker is reported using observed app state, without guessing its cause.
